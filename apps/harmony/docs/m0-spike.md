# M0 spike conclusions

Environment: DevEco Studio 26.0.1.290, HarmonyOS SDK 26.0.1.120 (API 26, Beta1),
`@deveco/deveco-cli` 1.3.0-stable, running `devphone` emulator (phone). Builds are
unsigned unless a local signing config is injected (S2).

## S1 — ArkTS version and decode style

Template compile options, as generated by `devecocli create --api-level 26`:

- `build-profile.json5`: `compatibleSdkVersion` / `targetSdkVersion` `"26.0.0"`;
  `strictMode: { caseSensitiveCheck: true, useNormalizedOHMUrl: true }`.
- `hvigor/hvigor-config.json5`: `modelVersion` `"26.0.0"`.
- SDK ets-loader: `arkTSVersion` defaults to **1.1** (only 1.0/1.1 are accepted); the
  ArkTS linter runs in STANDARD_MODE because `compatibleSdkVersion >= 10`;
  `targetESVersion` defaults to ES2021.

Conclusion: implement in the ArkTS 1.1 strict style; do not assume 1.2 static-only
semantics, and do not relax to 1.0.

Compile surface: **only files reachable from the entry are compiled.** A negative
control (an unreferenced file declaring `any`) built clean; the same declaration
inside `Index.ets` failed with ArkTS Compiler Error 10605008. Probes therefore stay
imported: the decode/guard probes from `EntryAbility.onCreate`, the component probe
as the shell's content.

Probes (`entry/src/main/ets/spike/`), all compiling and running on the emulator
(`EntryAbility` logs `decode=ok guard=probe`):

- `json-decode.ets`: `JSON.parse` → `Record<string, Object>` cast, per-field `typeof`
  checks, interface-typed object literal. No `any`/`unknown`, no unchecked payload cast.
- `type-guards.ets`: discriminated-union narrowing on a `kind` field plus `typeof`
  guards — the style the Phase 1 block decoders will use.
- `probe-card.ets`: `@ComponentV2` + `@Local` minimal component (also the M0 shell page).

Constraints hit while writing them, with the fixes the code now shows:

- Object-literal type aliases are forbidden (`arkts-no-obj-literals-as-types`) → use
  `interface`, not `type X = { … }`.
- Object literals must correspond to a declared class/interface
  (`arkts-no-untyped-obj-literals`) → annotate the target, never a bare literal.
- `any` is a compile error (10605008), not a warning.

## S2 — signing

The committed `build-profile.json5` keeps `signingConfigs: []` and no product
`signingConfig`, so CI and fresh clones build unsigned. A local debug build temporarily
injects a locally generated signing config (`devecocli signature generate`, or existing
local debug material for the same bundleName) and reverts the file before committing.
Signing material (`*.p12`, `*.cer`, `*.p7b`, `token.dek`, `token.enc`) is gitignored;
nothing signing-related is tracked. Verified: debug-signed `entry` and `entry@ohosTest`
HAPs install and run on the emulator.

## S3 — requestInStream SSE smoke

Source: `scripts/spike-sse-server.mjs` on the host, reached from the emulator at
`http://10.0.2.2:8787` (QEMU gateway; guest `eth0` is 10.0.2.15). Tests:
`entry/src/ohosTest/ets/test/SseSmoke.test.ets`.

- POST with a JSON body works; the server received `{"json":{}}` with the
  `text/event-stream` accept header.
- Each server write arrives as one `dataReceive` chunk: sizes `[41, 29, 12, 37, 32]`
  for the probe frame, the two halves of a split frame, heartbeat and done. No
  coalescing at this pace; a frame split across writes arrives as two chunks.
- `util.TextDecoder` streaming mode reassembles UTF-8 across chunks; the decoded text
  contains all four LF-framed events.
- Status-code ordering: `dataEnd` can fire **before** the `requestInStream` promise
  delivers the response code. Wait for both (`Promise.all`) instead of reading the
  code inside `dataEnd`.
- Abrupt close (server destroys the socket mid-frame): the partial bytes arrive first
  (one 30-byte chunk holding the incomplete frame), then the `requestInStream` promise
  **rejects** with `Transferred a partial file`. There is no clean `dataEnd`
  termination. The realtime layer must treat that rejection as a disconnect and
  reconnect; discarding the incomplete tail frame stays the parser's job.
- hypium runner gotcha: read `abilityDelegatorRegistry.getArguments()` inside `onRun`,
  not at module load — at load time it is null and every async case fails with
  `execute timeout 0ms`.

## S4 — asset smoke

`entry/src/ohosTest/ets/test/AssetSmoke.test.ets`: add → query (`RETURN_TYPE ALL`) →
remove round trip passes with `DEVICE_FIRST_UNLOCKED`; query after remove throws
(not found). Two findings:

- `remove()` rejects query-only tags: passing `RETURN_TYPE` errors with
  `Unsupported tag[asset.Tag.RETURN_TYPE] for the function`. Remove takes the alias alone.
- A fresh alias per run keeps the spike repeatable after an interrupted earlier run
  (asset add is not idempotent: a leftover alias errors with "The asset already exists").

## S5 — CI SDK feasibility (blocked locally, pending the runner)

A GitHub-hosted runner's SDK install cannot be verified from this machine.
`.github/workflows/harmony.yml` is the skeleton: hosted `macos-26`, pinned
`@deveco/deveco-cli`, command-line-tools restored from cache or downloaded from the
repository variables `HARMONY_CMDLINE_TOOLS_URL` / `HARMONY_CMDLINE_TOOLS_VERSION`.
The install step fails loudly until those variables are set — no guessed download
link and no silent skip. The first CI run after setting them is the S5 experiment;
the Linux fallback in design §8.4 applies only if hosted macOS cannot satisfy the SDK.
What is verified locally: clean unsigned macOS build in ~3s, and the instrumented
spikes on the emulator. hypium **local** (`src/test`) headless execution is not
exercised yet — M0 has no local tests, its spikes are instrumented (`ohosTest`).
