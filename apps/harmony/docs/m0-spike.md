## S1 — ArkTS version and decode style

Template compile options, as generated by `devecocli create --api-level 26`:

- `build-profile.json5`: `compatibleSdkVersion` / `targetSdkVersion` `"26.0.0"`;
  `strictMode: { caseSensitiveCheck: true, useNormalizedOHMUrl: true }`.
- `hvigor/hvigor-config.json5`: `modelVersion` `"26.0.0"`.
- SDK ets-loader: `arkTSVersion` defaults to **1.1** (only 1.0/1.1 are accepted); the
  ArkTS linter runs in STANDARD_MODE because `compatibleSdkVersion >= 10`;
  `targetESVersion` defaults to ES2021.

Conclusion: implement in the ArkTS 1.1 strict style; do not assume 1.2 static-only
semantics, and do not relax to 1.0.

Compile surface: **only files reachable from the entry are compiled.** A negative
control (an unreferenced file declaring `any`) built clean; the same declaration
inside `Index.ets` failed with ArkTS Compiler Error 10605008. Probes therefore stay
imported: the decode/guard probes from `EntryAbility.onCreate`, the component probe
as the shell's content.

Probes (`entry/src/main/ets/spike/`), all compiling and running on the emulator
(`EntryAbility` logs `decode=ok guard=probe`):

- `json-decode.ets`: `JSON.parse` → `Record<string, Object>` cast, per-field `typeof`
  checks, interface-typed object literal. No `any`/`unknown`, no unchecked payload cast.
- `type-guards.ets`: discriminated-union narrowing on a `kind` field plus `typeof`
  guards — the style the Phase 1 block decoders will use.
- `probe-card.ets`: `@ComponentV2` + `@Local` minimal component (also the M0 shell page).

Constraints hit while writing them, with the fixes the code now shows:

- Object-literal type aliases are forbidden (`arkts-no-obj-literals-as-types`) → use
  `interface`, not `type X = { … }`.
- Object literals must correspond to a declared class/interface
  (`arkts-no-untyped-obj-literals`) → annotate the target, never a bare literal.
- `any` is a compile error (10605008), not a warning.

## S3 — requestInStream SSE smoke

Source: `scripts/spike-sse-server.mjs` on the host, reached from the emulator at
`http://10.0.2.2:8787` (QEMU gateway; guest `eth0` is 10.0.2.15). Tests:
`entry/src/ohosTest/ets/test/SseSmoke.test.ets` (3 cases, all passing on the
emulator).

**Scope.** Design §7.2 S3 specifies this smoke against the local dev server
(`pnpm dev`). This round runs it against a **wire-format-equivalent fixture**
instead: the same POST + JSON body + `Accept: text/event-stream` request and
LF-framed `text/event-stream` response, but not the real RPC. Moving the
real-backend smoke (the first real `threads/subscribe`) into the M1 DoD is a
scope adjustment recorded here **pending owner approval**; `design.md` belongs
to the planning checkout and is not changed in this branch.

**Test assertions** — what `SseSmoke.test.ets` enforces:

- POST with `Accept: text/event-stream` resolves with code 200, and the decoded
  text contains all four frames: probe, split, heartbeat and done.
- The split frame carries `鸿蒙`. The server cuts 鸿 (U+9E3F, UTF-8 `E9 B8 BF`)
  after its first byte, so one character spans two writes by construction. The
  test asserts the fully reassembled frame
  `data: {"json":{"type":"split","seq":2,"text":"鸿蒙"}}` and that no U+FFFD
  replacement character appears: cross-chunk UTF-8 reassembly is asserted end
  to end, not inferred from chunk counts.
- A request with `Accept: application/json` is answered **400** (the fixture
  verifies the accept header).
- Abrupt close (`/sse-cut`, socket destroyed mid-frame): the `requestInStream`
  promise **rejects** with a message containing `partial`.

**Log observations** — hilog/server output of this run, not assertions:

- The server received `{"json":{}}` on `/sse` and `/sse-cut`.
- Each server write arrived as one `dataReceive` chunk: sizes
  `[41, 47, 10, 37, 32]` — probe, the two halves of the split frame (the
  47-byte chunk ends with `E9`, the 10-byte chunk starts with `B8 BF`),
  heartbeat, done. No coalescing at this pace.
- Status-code ordering: `dataEnd` can fire **before** the `requestInStream`
  promise delivers the response code; the test waits for both (`Promise.all`)
  by construction instead of reading the code inside `dataEnd`.
- Abrupt close: the partial bytes arrive first (one 30-byte chunk holding the
  incomplete frame), then the promise rejects with `Transferred a partial
  file`; there is no clean `dataEnd` termination. The realtime layer must treat
  that rejection as a disconnect and reconnect; discarding the incomplete tail
  frame stays the parser's job.

hypium runner gotcha: read `abilityDelegatorRegistry.getArguments()` inside `onRun`,
not at module load — at load time it is null and every async case fails with
`execute timeout 0ms`.

## S4 — asset smoke

`entry/src/ohosTest/ets/test/AssetSmoke.test.ets`: one case under
`DEVICE_FIRST_UNLOCKED`, covering the round trip and three negative paths with
the SDK's documented error codes — all asserted, none left as manual observation:

- add → query (`RETURN_TYPE ALL`) reads back the probe secret → remove →
  query rejects with **24000002** (the asset is not found).
- Duplicate add of the same alias rejects with **24000003** (the asset already
  exists): add is not idempotent. A fresh alias per run keeps the spike
  repeatable after an interrupted earlier run.
- remove with `RETURN_TYPE` rejects with **401** (parameter error) and message
  `Unsupported tag[asset.Tag.RETURN_TYPE] for the function`: remove takes the
  alias alone.

## S5 — CI SDK feasibility (not complete)

S5 is **not complete**: no hosted-runner run has produced an artifact yet, and no
Linux headless attempt has been recorded. Design §8/B-4 fixes the order: verify
**Linux headless first**; only if Linux is infeasible, GitHub-hosted macOS is the
preferred fallback (the repo already runs hosted `macos-26` for release and
screenshots); self-hosted runners are allowed only after hosted runners cannot
satisfy the SDK, under §8.4's isolation conditions. An earlier revision of this
document said "Linux is the fallback after macOS fails" — that reversed the
design order and is corrected here.

`.github/workflows/harmony.yml` is a skeleton wiring only the hosted macOS path:
hosted `macos-26`, pinned `@deveco/deveco-cli`, command-line-tools restored from
cache or downloaded from the repository variables `HARMONY_CMDLINE_TOOLS_URL` /
`HARMONY_CMDLINE_TOOLS_VERSION`. The install step fails loudly until those
variables are set — no guessed download link and no silent skip. The skeleton is
a starting point for calibration, not evidence that Linux was tried and failed.
**Calibration point: the first hosted CI run (draft PR) after the variables are
set**; the Linux headless attempt still owes its recorded result. What is
verified locally: clean unsigned macOS build in ~3s, and the instrumented spikes
on the emulator. hypium **local** (`src/test`) headless execution is not exercised
yet — M0 has no local tests, its spikes are instrumented (`ohosTest`).
