# M9 notes — models: connect a provider by key (slice 2)

Scope (design §7.2 M9, slice 2): the account's models directory and the connection form above
it. The Models page lists the saved connections, marks the one that runs the main model, and
leads with 连接模型 until the account can run one at all. The form picks a catalog provider, takes
its API key and its model; an OpenAI-compatible server takes its address, probes the models it
lists, and takes one of them. A new connection takes the main model only when the account has none
(`makeDefault`). Out of this slice: switching the main model among saved connections
(`setDefault`), OAuth sign-in, custom headers, the API-protocol picker and routing ids. Those
inputs stay absent, which the server reads as its default. The composer's send-failure row also
offers 添加模型 while the account has no model (mobile's failed-send behavior).

**Status: verified on the emulator.** Hypium 278/278 on the device, the real-backend smokes all
green against a local stack on real Postgres with a local OpenAI-compatible endpoint, and 7
captures in `apps/harmony/screenshots/`.

## Key decisions

- **The connect input's contract view is rebuilt from the intersection's own schema.**
  `models/connect` intersects `ModelConnectInputSchema` (itself refined) with surface/appVersion,
  and `headers` is a transformed record JSON toJSONSchema cannot express. `modelConnectInputView`
  uses `pickRefined` over the procedure input's picked keys, and the layer-1 test compares each
  field with the intersection's left member, so a field type drift goes red. This client sends no
  headers.
- **`makeDefault` is sent only when the account has no model.** ModelsPage computes it from
  `me.defaultProvider/defaultModel` (mobile's rule); with a default already set, a new connection
  is added beside it and never takes the main model.
- **`credentialId` is sent as an explicit null.** The contract reads null as "add another
  connection" and an omitted id as "update the provider's newest one" (older apps). ArkTS's
  `Record<string, Object>` cannot hold null literally, so the connect body carries it through a
  JSON-parsed placeholder. The fixture records `credentialIdWasNull` on every connect and keeps
  the omitted-id path as an update, and the device suite proves both.
- **`needsModel` drives the send-failure row.** While `me.needsModel` is true the row reads
  添加模型 and opens the models page; retrying the send cannot help without a model. Otherwise the
  row reads 重试, and 作为文件发送 for the image confirmation.
- **The Default tag is the account's own default, not the connection's field.** Each saved
  connection is compared with `me.defaultProvider/defaultModel` (canonical Pi provider id and the
  model id), never its own `isDefault`, which a save with `makeDefault: false` does not maintain.

## Known limitations

- **The key mask knows the typed key, not key shapes.** `hideKnownKey` masks the key as typed
  (case folded) and its JSON-escaped form; the reference sanitizer also drops provider-shaped key
  strings the message never carried as this request's key, which this client does not port.
- **A provider with no catalog name is shown by its id.** `providerDisplayName` falls back to the
  provider id when its catalog entry carries no `providerName` (older rows omit it).
- **A provider that needs a routing id cannot be configured here.** Azure's deployment id (and the
  other per-provider routing ids) has no field in this form; the contract leaves an absent id to
  the provider, so the connection saves but its requests fail until another client sets it.
- **The 添加模型 failure row was not walked on the device.** Reaching it needs a send that fails
  while the account has no model; the fixture does not stage that combination, so the row rests on
  the builds and mobile's rule, and the capture set has no shot of it.
- **A trailing-dot host differs between the kit's URL parser and the contract.** `@ohos.url`
  strips a trailing dot (`localhost.` → `localhost`) where WHATWG keeps it, so the normalized
  address loses the dot here; M1's endpoint note records the same kit difference.
