# 平台接入方案：IDONE、HomeONE、Reseller 与 TokenONE

- 日期：2026-11-03
- 状态：首期代码已接线；离线接口、隔离数据库及 Web 浏览器验证已执行。真实平台及原生系统回跳仍需部署验收。
- 本文替代此前讨论版本；最终计费决策为 TokenONE 独立计费，本项目关闭计费。
- 目标：尽量少修改已有文件，以新增文件承载接入逻辑，方便持续合并上游更新。
- 身份决策：以现有 Account 及已验证的 OIDC 绑定为唯一来源，不新增身份表或持久化复制 issuer/sub。

当前实现包括接口适配、现有 Account 身份读取、复用 ModelOAuthSession 的授权事务、API 与 worker 运行时取 Key、Web/Electron 与移动端入口、余额和充值导航。没有新增数据库结构。部署字段、实际支持范围和恢复方式见 [部署说明](self-host-model-account.md)。

内网部署：Reseller 服务端 `origin` 直接支持 HTTP 或 HTTPS，无需增加配置开关；授权页面、回调、模型地址及门户导航仍要求 HTTPS。HTTP 链路会明文传输应用凭据及用户 Key，应仅用于可信内网。

连接界面：成功后显示“已连接到 TokenONE”，不提供常驻“断开”按钮；历史断开结果未知时仍按需显示重试。Web／桌面与移动端保持一致。服务端诊断日志仅记录失败步骤、HTTP 状态及错误类别，不输出凭据、用户身份或上游响应正文。

按需授权：任务明确因模型授权暂停时，仅向任务本人显示“授权并继续”，点击后进入现有授权流程并恢复原任务，不自动弹窗。首次使用时 Web／桌面保留模型引导，移动端缺少可用模型时在登录后进入现有模型设置；有问卷时先完成问卷。任务状态由现有检查点派生一个只读标识，不新增存储；旧客户端继续显示文字提示并从设置授权。

## 1. 最终决策

TokenONE 独立负责模型余额、额度限制与实际扣费。本项目负责身份会话、业务权限、任务执行和模型调用，不维护第二套钱包，不同步平台余额，不新增 BillingProvider。

通过现有配置关闭本项目计费，保留上游订阅、积分及账务代码。用量记录可用于展示和排障，但不作为平台实际账单；实际扣费以 TokenONE 为准。

模型设置只展示平台账户授权及模型选择；普通连接管理页保留上游实现并隐藏入口。后台按原有凭据与模型选择规则执行。选用平台连接时，按用户绑定动态获取 Key，交给兼容模型运行时。

- 本项目支持标准 OIDC、PKCE、ID token 校验和显式账号绑定，并已有 Web、Electron、移动端认证流程。

## 5. 关闭本项目计费

优先使用现有配置，不删除计费代码、不修改历史账务。实施时验证：

1. 不装配现有订阅计费提供方。
2. API 与 worker 对计费关闭状态保持一致。
3. 订阅、积分购买和付费墙不显示或不启用。
4. 不执行本地模型额度预留、结算和余额检查。
5. 对话、定时任务、重试与备用模型不受本地订阅限制。
6. 平台连接使用用户凭据，不被识别为部署方托管积分模型。

若开关未覆盖某条路径，修正该通用开关的行为，不在各处增加平台专用判断。关闭开关的完整效果需要测试证明，不能仅凭未配置支付凭据认定已经完成。

TokenONE 的余额不足、账号停用、Key 限制和模型权限继续由模型服务执行。本项目展示余额不构成额度预留或调用成功承诺。

## 6. 登录接入

### 6.1 登录入口

三端复用现有 OIDC 客户端、账号绑定与本地会话，不要求额外经过 Reseller 登录／注册导航。应用已有 OIDC 配置即可完成身份认证；模型授权仍是独立流程。

```text
应用现有登录入口 → IDONE → 现有 OIDC 回调 → 本地会话
HomeONE 点击应用 → 应用独立 OIDC 启动入口 → 同一 OIDC 流程
```

独立启动入口保留供门户使用，普通登录页不无条件自动认证，避免退出或取消后循环。平台导航不创建本地登录凭据，应用仍自行检查业务角色、空间成员关系和数据权限。

### 6.2 配置

复用 OIDC_ISSUER、OIDC_CLIENT_ID、OIDC_CLIENT_SECRET、OIDC_NAME、OIDC_SCOPES 等已有配置。issuer 必须与 discovery 完全一致，回调精确登记。

是否关闭密码登录单独配置，不由平台接入自动决定。保持现有注册关闭、邮箱校验及账号显式绑定策略，不为了方便接入默认打开注册绕过。

OIDC 客户端密钥只保留在服务端。登录与模型授权使用不同事务，不能互相替代。单点登录不自动意味着跨应用单点退出。

## 7. Reseller 接口与模型调用

| 接口                                   | 用途               | 首期策略                         |
| -------------------------------------- | ------------------ | -------------------------------- |
| POST /api/apps/keys/ensure             | 读取已授权用户 Key | 模型调用准备时使用               |
| POST /api/apps/authorizations          | 启动模型授权       | 用户主动触发                     |
| POST /api/apps/authorizations/complete | 兑换授权结果       | 服务端一次性事务                 |
| POST /api/apps/authorizations/revoke   | 撤销模型授权       | 用户主动断开                     |
| POST /api/apps/balance/query           | 本人余额           | 页面进入或手动刷新               |
| GET /api/apps/groups                   | 应用默认分组       | 仅在实际需要展示或检查配置时使用 |

申请最小 scopes：keys:ensure、balance:read；确需查询分组时增加 groups:read。首期不申请 pricing:read。由平台配置默认分组、应用状态及精确模型授权回调地址。

模型请求使用 ensure 返回的用户 Key 调用配置的 TokenONE 模型服务，不能使用 Reseller 应用凭据调用模型。服务 origin 与模型 base URL 分开配置，协议和模型能力复用现有连接设置。

ensure 不创建或替换 Key。只有明确返回 APP_USER_AUTHORIZATION_REQUIRED 才进入授权流程，其他服务错误不能伪装成需要重新授权。

## 8. 凭据设计

### 8.1 配置与运行时分离

| 信息                           | 保存与使用                                 |
| ------------------------------ | ------------------------------------------ |
| 模型地址、协议、启用模型、能力 | 复用现有连接配置                           |
| 外部凭据来源与连接状态         | 优先复用现有连接结构，仅补充实际缺少的字段 |
| 用户身份                       | 从现有 Account 读取，不另建身份存储        |
| 用户模型 Key                   | 首期仅服务端运行时使用，不长期缓存         |
| 平台余额                       | 只读展示，不写入本地积分账本               |

读取设置只读取连接配置与本地连接状态，不调用 ensure，也不将本地状态当作上游授权仍有效的证明。实际模型调用准备时检查执行身份、连接所有者、空间权限与现有 Account 绑定，再调用 ensure。

需要覆盖主模型、备用模型、连接探测、后台任务、重试及其他实际调用模型的入口。实现前先建立“调用路径—凭据解析入口—执行身份”清单，确认没有旁路。

首期不做跨任务 Key 缓存。取得的 Key 不写入普通连接、任务参数、消息、日志或前端响应。模型 endpoint 由可信配置确定；外部授权连接不能允许用户通过修改地址把运行时 Key 发送到任意服务。

### 8.2 执行身份与失败行为

沿用 run.userId 及现有连接所有权规则，不默认为空间管理员承担费用，不允许跨用户借用连接。若某条后台路径没有可确定的授权用户，安全停止该平台调用，不能回退到部署身份。

- 需要授权：停止当前平台调用，显示授权操作。
- 服务暂时故障：有界重试，保留会话和任务。
- 余额不足、账号停用或模型权限拒绝：停止，不创建或切换 Key 绕过限制。
- 不自动回退到部署密钥或其他用户凭据。
- 备用连接仅执行用户明确配置且允许的策略，不因接入而增加隐式付费来源切换。

## 9. 可信身份与授权事务

### 9.1 复用现有身份来源

Reseller 要求原始 issuer/sub。本项目从已验证并保存的 OIDC 绑定读取身份，不能接受浏览器提供的 subject，不能按邮箱或昵称推断。

现有 Account 已关联本地用户，并保存 ID token。封装服务端身份读取函数，复用现有解密及 issuer、subject 与 accountId 的绑定校验，返回当前配置 issuer 对应的可信身份。历史 ID token 只作为已验证绑定的身份来源，不作为当前登录或近期认证证明；不能接受客户端上传的 token 替代数据库中的可信来源。

不新增身份表、不复制 issuer/sub、不维护第二套身份同步或解绑逻辑。若连接语义确实需要固定具体身份，只保存对现有 Account 的必要引用；实施时先核对现有结构，不能预先认定需要新增字段或关联表。

API 与 worker 使用同一身份读取契约。实施前核对 worker 已有的密钥访问权限和包依赖，选择最小接线方式；不为尚未证实的权限问题预先增加身份缓存表或内部身份服务，也不默认向 worker 分发更多认证密钥。该接线方式尚未验证，是实施前的明确检查项。

后台执行无需浏览器保持在线，但必须检查用户状态、现有 Account 绑定与任务权限。解绑、删除账号或切换 issuer 后，原身份对应的平台调用应安全拒绝；重新绑定不能悄悄把旧任务切换到另一个人的钱包。身份缺失、无法解密、绑定校验失败或选择有歧义时停止调用，不按邮箱回退。

### 9.2 事务状态

授权事务使用 Postgres，绑定用户、原会话、身份、origin、精确回调地址、PKCE、凭据版本、返回页面和有效期。敏感事务材料受保护，不保存到浏览器 URL 或日志。

事务中的身份绑定使用现有 Account 引用及必要的变化校验信息，仅用于短期流程校验，不建立永久身份副本。先评估现有 ModelOAuthSession 的存储、加密和原子操作；其现有接续语义不能直接硬套，只有确实缺少必要状态时才扩展结构或新增事务表。

```text
待回调 → 兑换中 → 成功 / 结果未知 / 失败
```

- state 与 verifier 使用安全随机值，按接口要求实施 S256 PKCE。
- 回调先检查 state、有效期、原会话和身份，再原子领取兑换权限。
- 拒绝重复参数、重放、身份变化及未登记 origin。
- 兑换校验发起时的应用凭据指纹；凭据轮换使在途事务失效，由用户重新发起，不建设凭据版本管理系统。
- 兑换响应丢失时进入结果未知，先 ensure 恢复，不盲目重放 code。
- 网络等待不持有数据库事务锁；多实例通过原子领取和事务状态协调，结果未知时，三端共享客户端在读取状态后自动请求一次恢复；服务端仅对原会话、原身份的未知兑换调用 ensure 并原子消费事务，不重新兑换 code、不自动发起授权。确认失败才展示重试，不新增后台恢复循环。
- 不使用全局串行队列或全局并发槽阻塞无关用户。
- 回调清除地址栏 code/state，响应 no-store，禁止认证查询参数进入访问日志和 APM。

授权成功仅恢复明确因同一账户绑定的模型授权而暂停的原任务，沿用原 runId 和执行器幂等机制。不重建任务、不重放已完成任务或其他审批等待，不因刷新或回调重复执行收费操作。

### 9.3 撤销

用户断开时立即阻止本地新的平台调用，调用 revoke；只有上游确认后显示已断开。结果未知保留待确认状态并允许有界恢复。

撤销会阻止继续取 Key，但不承诺取消已发出的模型请求，也不承诺上游已发 Key 立即失效。实际停用、额度和撤销时效需独立验收。

## 10. 余额、导航与错误处理

余额代理只查询当前登录用户，不接受任意身份参数。页面进入、手动刷新、浏览器恢复焦点或移动端回到前台时读取，不自动轮询。保持金额精度与单位，不自行换算成本地积分。

查询失败显示不可用，不能显示伪造零余额。退出或切换账号时清理旧数据，并取消或忽略旧账号在途响应。上游应用凭据失效不能当作本地登录失效。

充值使用 HomeONE 发布的导航地址，不新增应用充值 API。导航 Cookie 仅表示导航偏好，必须校验目标，不影响鉴权或扣费。

首期公共域名优先，渠道域名按实际登记接入。超过平台授权回调登记范围时不得偷偷回落到另一个域名或放宽 Cookie 范围。

可选导航脚本只在配置的平台部署启用，来源需可信，CSP 按具体资源合并，不放宽全部来源。不把品牌脚本无条件注入所有自托管实例。

上游响应必须做字段及类型校验，保留字符串 ID，处理余额与其他接口不同的响应结构。请求设置超时、取消和有界重试，不转发原始错误正文或敏感响应；日志只保留脱敏类别与关联 ID。

## 11. 多端策略

| 端       | 交付要求                                                                     |
| -------- | ---------------------------------------------------------------------------- |
| Web      | 同源会话绑定，当前页跳转授权并返回原 URL，恢复已保存的文字草稿与模型设置面板 |
| Electron | 验证同会话弹窗、回调及外部导航，不把远程授权页暴露给特权桥                   |
| 移动端   | 单独验证模型授权的浏览器会话交接与回跳，不在 URL 传 Bearer token             |

共享后端契约、状态与错误处理，只有导航及安全存储保持平台实现。原生端不直接加载 Web 浮动脚本。

移动端已实现一次性浏览器启动票据与回跳：系统浏览器通过启动入口取得专用事务 Cookie，回调检查原应用会话仍有效，随后返回固定应用 scheme，不在 URL 交接登录凭据。系统级真实回跳仍需在设备上验收。桌面复用已有 SSO 弹窗和回调通道；原生端登录保留现有 OIDC 流程。首页与充值使用 HomeONE 公共导航策略，Web／Electron 精确校验渠道导航 Cookie，移动端使用平台默认值。三端均保留原有 OIDC 登录／注册流程，不增加强制平台登录跳转。

## 12. 代码组织与上游维护

采用“通用扩展点 + 独立适配实现 + 少量入口接线”。优先在已有包内新增文件，避免新建大量包和依赖关系。

| 位置                 | 新增职责                                              | 预计已有文件改动                                 |
| -------------------- | ----------------------------------------------------- | ------------------------------------------------ |
| packages/adapter-kit | 通用授权与运行时凭据接口                              | 必要的接口或导出                                 |
| packages/adapters    | Reseller 客户端、校验、错误转换                       | 适配装配与共用凭据入口                           |
| packages/auth        | 可信身份读取                                          | 通用读取入口及导出                               |
| packages/db          | 复用 Account 与现有授权存储，按缺口补充连接或事务状态 | 仅确有需要时修改 schema 和增加迁移；不新增身份表 |
| apps/api             | 授权、回调、撤销、余额路由                            | 路由与依赖注册                                   |
| Web、移动端          | 平台连接、余额、导航                                  | 少量路由与设置入口                               |
| API、worker 装配层   | 同一凭据解析能力                                      | 必要的依赖注入                                   |

以上是范围估计，实施前不承诺精确文件数量。新增协议逻辑集中在新文件，已有文件主要注册和调用。

厂商名称、配置与协议翻译只存在适配器和装配层；公共契约、数据库字段、产品路由及 UI 使用通用概念。模型行为使用已有连接设置，不新增模型专属环境变量。不需要的外部依赖仅在配置后延迟加载，能使用直接 HTTP API 时不引入额外 SDK。

不复制 API 启动器或执行器，不用猴子补丁，不通过反向代理注入认证逻辑。减少重复实现比机械减少修改文件数量更重要。

提交分组：

1. 通用扩展点与离线测试。
2. 独立平台适配实现与契约测试。
3. 部署配置、UI 入口、文档与验收。

## 13. 迁移、发布与回滚

优先复用现有数据库结构，仅在确认缺口后增量添加必要字段、约束或授权事务表，不新增身份存储。新数据格式也需评估旧代码行为；加字段不自动意味着行为兼容。

发布顺序：

1. 部署增量迁移及兼容读取能力，接入默认关闭。
2. 更新 API 和 worker。
3. 确认旧 worker 及运行中任务退出。
4. 开启外部连接创建和调用。

回滚前关闭新授权与新调用，处理在途任务，再回退程序。验证旧版本不会把新增凭据误当普通 Key，不会自动使用默认密钥。若无法证明安全回退，保留兼容版本读取能力，不直接回退到不认识新格式的版本。

发布保留历史凭据、模型选择和账务记录，部署密钥通过部署环境提供。

## 15. 验收标准

先使用离线 mock 和隔离 Postgres fixture，不修改线上账号或数据。

- [ ] 关闭计费后无订阅门槛、积分购买、本地预留或结算。
- [ ] OIDC 复用已有绑定策略，不能伪造 issuer/sub。
- [ ] 身份仅来自现有 Account，无新增身份表或永久 issuer/sub 副本。
- [ ] API 与 worker 的身份读取及密钥访问经过验证，身份缺失或有歧义时安全拒绝。
- [ ] 旧账号显式绑定正常，取消和退出不进入重定向循环。
- [ ] 普通对话、后台任务及其他模型路径都使用正确用户凭据。

- [ ] 平台失败不会清除本地会话或切换部署密钥。

## 17. 已补齐的操作体验

- Web 在当前页跳转授权并返回原 URL，复用已有草稿存储恢复文字与提及；仅驻留内存的未发送附件不跨整页跳转恢复。桌面保留原生授权窗口，移动端返回上一个页面。
- 因模型授权而暂停的任务，在同一账户授权恢复后继续使用原任务编号；不自动重放其他任务。
- 保留独立模型授权流程，移除额外的绑定 SSO 入口，三端继续复用现有 OIDC 登录。正常连接时隐藏授权操作；未授权时显示首次授权，授权未完成或确认失效时显示重新授权。未知结果先自动确认，失败后才显示重试；断开失败时才显示重试断开。缺少可信 OIDC 身份时提示使用现有 SSO 登录，不新增绑定流程，结果未知不会伪装成功。
- 余额支持手动刷新，以及充值返回后的焦点／前台刷新，无自动轮询。
- 托管连接仍可用于模型选择，但从普通密钥编辑列表和管理菜单中排除；移动端直达编辑页也只显示模型账户管理。

本轮验证：435 项单元／回归测试、19 项隔离 PostgreSQL 集成测试、5 项浏览器测试通过；API、worker、Web、移动端类型检查及 Web 构建通过。覆盖首次／重新授权后的页面和草稿保留、未知结果自动确认与失败重试、断开失败重试、恢复期间撤销防护，以及同一任务授权后续跑。现有移动端 SSO 登录文件无改动。浏览器测试使用虚构平台响应，数据库测试使用隔离实例；真实平台收费及原生系统浏览器回跳仍需部署环境验收。

## 配置简化修订

部署连接只需 provider、Reseller origin、应用 credential 与模型 baseUrl。authorizationOrigins 不再必填，返回授权地址保留 HTTPS／无 userinfo／无 fragment 校验；旧的显式白名单继续生效。HomeONE 默认入口与 CreativeOne 一致，可选 navigationOrigin 仅用于自建入口。首页和充值从公开 /auth.json 的导航策略获取，不要求 homeUrl 或 rechargeUrl。Web／Electron 校验渠道 Cookie 的目的地址与平台策略精确匹配；移动端使用平台默认地址。导航不可用时隐藏链接，不阻断模型授权。

授权后使用临时用户 Key 查询 /models，模型列表进入原有模型选择器，保留已有平台模型选择；既有模型选择保留，用户可在模型账户页选择平台模型。模型协议默认 Chat Completions，可在模型账户设置中切换 Responses，不在部署 JSON 中必填 modelId、kind、apiProtocol 或 enabledModelIds。旧 model 结构保留兼容。重新授权会保留用户选择的协议，协议切换不自动发送或重试收费调用。

首次使用的连接模型引导页复用已有模型设置面板，支持先授权再选择主模型；Web 授权返回精确的 /onboarding/model 路径，并通过已有 settings 查询参数恢复模型面板；桌面保留原生回调。移动端继续通过原生模型设置与模型选择器完成相同流程。
